# Department leads as operational managers
An active office Employee appointed Department Lead inherits the standard Branch Manager operational grants, not a new persisted role. No finance/admin/reviewer privileges are granted. A lead may manage assets and employees in their led active departments only. The standard six grants are shared with Branch Manager seed; custom role changes are not automatically inherited.
Resource department ownership is explicit and nullable. Admin assigns available/retired stock via Add/Edit Resource > Specifications > Department. Existing allocated stock with one identifiable current office custodian is backfilled by migration; other records remain unallocated until admin review. New office assignments set ownership from recipient department; return retains allocation. Department lead issuance requires resource and recipient in the same led department. Transfers support distinct office departments or physical branches, with ownership changed only on receipt. Legacy umbrella branches still excluded from transfer selection. Existing manager workflow, approval and receipt unchanged.
Inventory and Maintenance still UI preview modules for both types of managers. Full backend to be implemented with same scope. Existing non-employee back-office roles keep their original permissions. Historical resource audit for leads is limited to department-tagged events within scope.
Use backed-up staging DB, db:generate and db:deploy; no reset. Test via separate manager logins. CI runs on an isolated DB only.
